# Value Noise 轴对齐问题：为什么球面会出现规律性凸起带

## 问题现象

在 icosphere 星球表面，顶点位移后会出现近似水平的、有规律的凸起条带，而非预期的随机地形。条带间距均匀，与球体经线/纬线走向大致吻合。

---

## 根本原因：3D 值噪声的格栅是轴对齐的

### 值噪声的工作原理

`noise_gen.wgsl` 中的 `noise3` 函数是标准的 3D 值噪声：

```wgsl
fn noise3(p: vec3<f32>) -> f32 {
  let ip = floor(p);          // 找到 p 所在的整数格子
  let fp = fract(p);          // p 在格子内的偏移
  let u  = fp * fp * (3.0 - 2.0 * fp);  // smoothstep 插值权重
  let n  = ip.x + ip.y * 157.0 + ip.z * 113.0;
  // 插值 8 个角点的 hash 值
  ...
}
```

其核心结构是：将 3D 空间划分为**边长为 1 的立方体格栅**，在每个整数坐标顶点处放置一个随机值，然后在格子内部做三线性插值。这个格栅的轴线与世界坐标系的 X / Y / Z 轴完全对齐。

### 球面与格栅的几何关系

球面是一个曲面，但格栅是平直的。当球面以频率 `freq` 采样噪声时，实际采样位置是 `pos * freq`，即球面顶点被均匀缩放后落在格栅空间中。

问题出在**球面与格栅平面的交线**上。

以 Y 轴为例：格栅在 `floor(y) = 0, 1, 2, ...` 处有整数层分界面。球面在恒定纬度（Y 值固定）处形成一个纬线圈，而**这个纬线圈与某条格栅层分界面平行**。当纬线圈恰好穿越格栅的整数层边界时，该位置的噪声值在格子内插值从接近一个值跳变到接近另一个值，形成一条可见的"阶梯"。

更直观地说：

```
Y = 2.0 ─────────────── 格栅层分界 ─── 噪声值突变线
          球面纬线圈穿越此处 → 一整圈顶点同时受到阶梯影响
Y = 1.9
Y = 1.0 ─────────────── 格栅层分界 ─── 噪声值突变线
Y = 0.9
Y = 0.0 ─────────────── 格栅层分界 ─── 噪声值突变线
```

球面上的每一圈纬线都会在对应的格栅层处经历相似的突变，于是产生**等间距的水平条带**。

### FBM 放大了这个问题

`fbm` 函数叠加了 6 个倍频：

```wgsl
fn fbm(p: vec3<f32>, freq: f32, octaves: i32, persistence: f32) -> f32 {
  // 每个 octave 将频率翻倍
  f *= 2.0;
}
```

每个倍频的格栅间距是上一级的一半，产生的条带也随之加倍密集。6 个倍频就意味着叠加了 6 套不同密度的条带系统。这些条带在视觉上相互叠加，虽然表面上看起来更"复杂"，但规律性并未消失——只是变成了多个频率的周期性图案混叠。

### 为什么在随机噪声上看不出来，在球面上却看得出来

在平面上（如地形 heightmap），噪声的轴对齐性不明显，因为视角和采样方向是随意的。但**球面有一个特殊性质：它本身就是对称的**。

- 同一纬度的所有顶点，其世界 Y 坐标完全相同
- icosphere 的顶点在纬度方向上是分层分布的（每层顶点数大致相同）
- 因此，同一层顶点会同时穿越同一条格栅分界面，产生统一的位移响应

结果是：**纬线圈上的所有顶点同相位地被推高或推低**，形成肉眼可见的环形凸起。

---

## 为什么值噪声特别容易出现这个问题

值噪声（Value Noise）与梯度噪声（Perlin Noise / Simplex Noise）的根本区别：

| | 值噪声 | 梯度噪声（Perlin） |
|---|---|---|
| 格子顶点存储的是 | 随机**值** | 随机**梯度向量** |
| 格子内部的行为 | 在随机值之间做插值，导数在边界处不连续 | 梯度控制导数，边界处导数为 0 |
| 格栅边界处的表现 | 有明显的"平台"和"斜坡"交替，格栅线可见 | 格栅边界处导数归零，视觉上格栅线消失 |

值噪声的格子边界处，插值权重 `u = smoothstep(fp)` 的导数虽然为 0（保证了 C1 连续），但**一阶导数本身在格子边界两侧不对称**——左侧梯度与右侧梯度不一致，这在视觉上仍会留下可察觉的"折痕"。

Perlin 噪声通过在每个格子顶点存储随机梯度向量，并要求格子边界处贡献的梯度项为零，从根本上消除了这种不对称性。

---

## 结论

当前实现使用的值噪声在球面上必然产生规律性条带，这**不是参数调整能根治的问题**，而是算法选择的结构性缺陷。

要彻底解决，需要将 `noise3` / `fbm` / `ridged` 替换为 3D 梯度噪声（Perlin Noise）或 Simplex Noise 实现。如果要保留值噪声，可以加入 **Domain Warping**（用另一层噪声扰动采样坐标），在一定程度上破坏条带的规律性，但无法从根本上消除。
